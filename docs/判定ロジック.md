# 漢字の正誤判定ロジック

「カンジノート」の書き取り判定は `index.html` に埋め込まれた `KanjiJudge` が担う。
児童に身につけてほしい **書き順・字形・止めはね・点画の交差** を、それぞれ独立に評価して
「どこをどう直すか」を名指しで返すことを目的とする。

エンジン本体は次の目印の間にある。DOM にも React にも依存しない純粋な関数だけで書かれており、
`test/helpers.js` がこの範囲を取り出して試験する（配信されるコードそのものを試験している）。

```
// ==== KANJI_JUDGE_ENGINE_START ====
// ==== KANJI_JUDGE_ENGINE_END ====
```

## 手本データ

[KanjiVG](https://github.com/KanjiVG/kanjivg)（CC BY-SA 3.0）の SVG を使う。
1 つの `<path>` が 1 画に対応し、`d` に形が、`kvg:type` に画の種別（㇐ 横、㇒ 撇 など）が入っている。

`d` の解析は `KanjiJudge.parsePath()` が自前で行う。以前は非表示の SVG 要素を DOM に挿して
`getPointAtLength()` を呼んでいたが、自前解析にしたことで判定全体が Node で試験できるようになった。

## 5 つの観点（合計 100 点）

| 観点 | 配点 | 見ているもの |
| --- | --- | --- |
| 字形 | 30 | 位置合わせ後に、線の形そのものが手本とどれだけ重なるか |
| 配置 | 10 | 文字全体の中心のずれと大きさの比 |
| 書き順 | 25 | 何画目に書いた線が、手本の何画目にあたるか |
| 点画の交差 | 20 | 画どうしが「突き抜ける／接する／離れる」のどれか |
| 終筆 | 15 | とめ・はね・はらい |

### 合否

次のいずれかがあれば、点数にかかわらず不合格（練習モードへ）とする。
書き順や交差は「おしい」で通してしまうと誤ったまま覚えてしまうため。

- 画数が違う
- 点画の交差の有無が違う
- 書き順が違う
- 画を書く向きが逆（横画を右から左へ、など）

それ以外は 60 点以上で合格。90 点以上で 3 点、75 点以上で 2 点、それ未満は 1 点。

## 各観点の考え方

### 字形と配置を分けて測る

まず文字全体の重心と広がりを手本に合わせる（平行移動と拡大縮小のみ。**回転は正さない** —
傾いて書いたのは誤りなので、正すと見逃してしまう）。

- **字形** = 位置合わせ後の、対応する画どうしの平均のずれ
- **配置** = 位置合わせに必要だった移動量と倍率

こうすると「形は取れているが小さい」と「大きさは合っているが形が崩れている」を区別して伝えられる。

なお字形は、画を 48 点に等間隔でリサンプリングして各点の距離を平均する。始点と終点だけを見る方式では、
途中が大きく曲がっていても満点になってしまう。

### 書き順は最適な対応づけで決める

「児童の i 画目」と「手本の j 画目」の全組み合わせについて形の近さを求め、
**ハンガリー法**で全体の費用が最小になる対応づけを 1 つ選ぶ。その対応が
1→1, 2→2, … でなければ書き順の誤りとし、「かきじゅんが ちがうよ」と返す。

始点が近い画へ順に貪欲に割り当てる方式だと、「三」のように同じ形の画が並ぶ字で、
位置が少しずれただけの正しい答えを誤りと言ってしまう。全体最適で決めればこれが起きない
（`test/judge.test.js` の「同じ形の画が並ぶ字でも…」が守っている）。

書く向きが逆かどうかは、画を反転して比べた方がよく一致するかで判定する。

### 点画の交差は「突き抜けた長さ」で見る

2 画の関係を 3 つに分ける。

- `cross`（突き抜けている） … 交点があり、交点から**両方の画の端まで**の長さが 0.05 以上
- `touch`（接している） … 交点があるが端に近い、または交わらずに 0.045 以内まで近づいている
- `apart`（離れている）

「交点から端までの長さ」を見るのが要で、これにより「十」のような突き抜けと、
「口」の角のような接続を区別できる。手本と児童で関係が食い違えば不合格にする。

> 以前のロジックは「交差している線分の対の数が 3 以上か」で判定していた。
> しかし滑らかな 2 本の線が普通に交差したときの対の数は 1 なので、
> 正しい「十」も、縦画が横画に届いていない「十」も、どちらも「交差なし」と判定されていた。
> つまり交差の判定は事実上働いていなかった。

### 終筆（とめ・はね・はらい）

- **はね** は形で判定する。画の末尾に、全体の 4.5〜20% の長さで、
  それまでの進行方向から 65 度以上向きが変わる「尾」があれば、はね。
  手本にも児童の線にも同じ判定を使うので基準がぶれない。
- **はらい／とめ** は筆の速さで判定する。末尾 15% の平均速度が全体の平均速度の
  0.9 倍以上ならはらい、0.55 倍以下ならとめ。この判定のために、
  手書きの各点には時刻 `t` を記録している。中間の速さだったときは断定せず、部分点にする。

手本側の期待値は、**形を第一の根拠**にする。`kvg:type` の鉤系（㇖ など）には、
実際には「おれ」で止める画も含まれるため（「子」の 1 画目と「字」の 3 画目は同じ ㇖ だが、
前者はとめ、後者ははね）、種別ではなく描かれている形で決める。
はらいの判定にだけ `kvg:type`（㇒ ㇓ ㇏ など）を使う。
点（㇔）と極端に短い画は、とめ・はらいを問う意味がないので対象外にする。

### 画数

画数が違えば不合格。ただし次の手当てをしてから判定する。

- ペンが浮いて 1 画が 2 つに割れた場合（間隔 0.07 以内）は、つなぎ直してから採点する
- 足りない画があれば「3かくめが たりないよ」と何画目かまで伝える

## フィードバック

読み手は低学年の児童で、指摘は数秒しか画面に出ない。長い説明文は読み終わる前に消えてしまい、
結局なにも伝わらない。そこで **短く・1 つだけ・大きく** を原則にする。

### 文は 1 行の短文にする

`judge()` は指摘を重い順に `messages` に返すが、画面に出すのはその先頭 1 件だけにしている。

| 観点 | 返す文 |
| --- | --- |
| 画数 | `3かくめが たりないよ` / `かくすうは 5 かくだよ` |
| 書き順 | `かきじゅんが ちがうよ` |
| 向き | `3かくめは ぎゃくむき` |
| 終筆 | `3かくめは はねる`（とめる／はらう） |
| 交差 | `3かくめは つきぬけるよ`（つきぬけないよ／くっつけるよ／はなして かくよ） |

画の番号は算用数字で書く。お手本に添える番号（①②…）と同じ表記でないと、
文と画面の線が児童のなかで結びつかないため。

交差の指摘は 2 画のうち「直す側」の番号だけを出す。番号を 2 つ並べると、
どちらを動かせばよいのかを読み解く手間がふえる。

短文であることは `test/judge.test.js` の「指摘の文はどれも短い 1 行になっている」で守っている。

### お手本は「グレー＋つぎの 1 画だけ赤」

不合格のときはお手本を 1 画ずつ描き、書き順の番号を添える。色は 2 色だけ。

- **グレー** … 書き終わった画も、これから書く画も
- **赤** … つぎに書く 1 画

練習モードでは 1 画 書くごとに赤が次の画へ進むので、目で追う先がつねに 1 つに絞られる。
複数の画を同時に色分けすると、どれから手をつければよいのかが分からなくなる。

## 試験

```
npm test
```

`test/kanjivg-fixtures.js` には実際の KanjiVG から採った 11 字分の手本データと、
書写指導に基づく終筆・交差の正解ラベルが入っている。閾値を変えたらここが崩れないか確かめること。
